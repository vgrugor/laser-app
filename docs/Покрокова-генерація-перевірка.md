# Перевірка покрокової генерації

Ця інструкція описує завершений цикл для комплекту панелей. [Робота з панелями](Комплекти-панелей.md) містить опис кнопок і статусів.

## Сценарій у майстерні

1. Створіть шкатулку з кришкою 200 × 150 мм, довгою стінкою 200 × 60 мм і короткою 150 × 60 мм. За потреби додайте повтори стінок через «Той самий декор, що й». Виберіть палітру та концепцію.
2. Відкрийте кришку й натисніть «Згенерувати панель». Перегляньте результат. «Інший варіант панелі» запускає наступну спробу цієї кришки. Доступні попередні картинки залишаються у «Варіантах цієї панелі».
3. Коли кришка подобається, натисніть «Обрати й перейти далі». Наступна панель відкриється без запуску генерації. Створіть і оберіть довгу, потім коротку стінку. Точні повтори використовують зображення вихідної панелі; вибір кожної панелі підтверджується окремо.
4. Після останнього вибору відкриється «Загальний вигляд». Запустіть його окремою кнопкою. Готові декори панелей використовуються як джерела. За потреби окремо запустіть повну перевірку ШІ або створення контурів.
5. Прийміть виріб. Зауваження ШІ можна свідомо прийняти через відповідний діалог; ручна позначка «Потрібна правка» потребує виправлення. Експортуйте JSON для резервної копії; ZIP зручний для окремих файлів панелей і паспорта.
6. Для перевірки історії відкрийте окремий варіант погодженого виробу, поверніть попередній декор кришки й порівняйте стінки: вони мають лишитися без змін. Виберіть кришку повторно та вручну оновіть загальний вигляд. Попередній вигляд залишається видимим до оновлення.

Нові зображення використовують ресурси підписки. Для перевірки коду без генерації призначені автоматичні тести нижче.

## Сумісність і резервні копії

| Дані | Очікувана поведінка |
| --- | --- |
| Старий проєкт без `panels` | Відкривається як одна панель; зображення, ID, дати, версії та попереднє погодження зберігаються. |
| Раніше погоджений комплект без позначок вибору | Залишається доступним у збережених виробах. Нові позначки «Обрана» автоматично не додаються. |
| Старий загальний вигляд без прив’язки до джерел | Показується як збережений. Прив’язка з’являється після явної генерації, перевірки комплекту або ручного прийняття. |
| Поточний JSON-експорт | Містить вбудовані зображення, концепції, версії, вибір панелей, локальну історію, підготовку й контури. Імпорт зберігає вибір панелей; прийняття всього виробу та ручні перевірки виконуються заново. |
| Застарілий загальний вигляд | Залишається застарілим після експорту/імпорту, навіть якщо файли вдалося завантажити. |
| Відновлення версії проєкту | Повертає весь збережений стан; накопичена локальна історія панелей із тими самими ID зберігається. Помилки, цілі повторного запуску й активні завдання з попереднього стану очищаються. |
| Відновлення варіанта однієї панелі | Повертає цю панель та її точні повтори. Незалежні панелі зберігаються, загальний вигляд потребує оновлення. |
| Скасування / перезапуск сервера | Завершені часткові файли та текстова підготовка лишаються доступними. Повторний запуск використовує збережену ціль; зміна відкритої панелі її не перенаправляє. |

Формат JSON залишається `plywood-flow-project`, версія 1; версія локального сховища — 2. Нові поля додаткові. Збережені локально погодження зберігаються, а JSON-імпорт продовжує вимагати нового прийняття. Локальна історія обмежена 20 різними зображеннями на панель, історія версій проєкту — 20 станами. Експорт не змінює поточний проєкт; при помилці читання файла він припиняється.

## Автоматичні перевірки

Звичайний запуск у Terminal:

```sh
npm run check
npm test
```

Тести використовують локальні PNG, підставні відповіді генератора й тимчасові каталоги. Codex SDK і генерація зображень не викликаються. Тест HTTP-життєвого циклу тимчасово відкриває порт на `127.0.0.1`.

Для середовища, де заборонено відкривати порти:

```sh
node --test --test-skip-pattern='local HTTP lifecycle' tests/*.test.mjs
```

Цей запуск виключає один тест справжнього TCP-з’єднання. Окрема перевірка HTTP-обробників у процесі охоплює токен, Origin, блокування паралельного запуску, доступ до часткового PNG, скасування, запис на диск та відновлення серверного завдання.

Основні регресійні сценарії:

- `tests/panels.test.mjs`: повторні спроби кришки, повторне використання підготовки, вибрані референси стилю, точні копії, стінки, переривання, перезавантаження, фінальний вигляд та локальне відновлення.
- `tests/project-transfer.test.mjs`: справжні функції експорту/імпорту/відновлення версій, старий формат, одна явна панель, комплект, вибір, кеш, контури, прив’язка preview та неприпустимі дані.
- `tests/panel-history.test.mjs`: незалежність панелей, межа історії, застарілі параметри й правила, експорт контурів, успадкування та відновлення історії.
- `tests/product-completion.test.mjs`: умови завершення, актуальність preview, необов’язкова перевірка ШІ та прийняття старих комплектів.
- `tests/workflow.test.mjs`: часткові файли, життєвий цикл завдання та відновлення після перезапуску.

Ці перевірки підтверджують логіку застосунку. Художню якість, точність перенесення декору у вигляд виробу й придатність до виготовлення потрібно оцінити на реальних результатах. Розміри, перемички від 2 мм та геометрію різання перевіряйте у SolidWorks.
