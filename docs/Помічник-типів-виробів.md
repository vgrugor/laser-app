# Помічник зі створення типів виробів

Помічник — окрема текстова роль Codex SDK, доступна в розділі **Типи виробів → Створити тип з помічником**. Для підключення нового маршруту потрібно перезапустити локальний сервер. Наявні API-ключі не використовуються: виконується той самий локальний SDK runner зі штатним входом ChatGPT.

## Сценарій

1. Користувач описує клас виробів, а не сюжет окремого виробу.
2. Помічник зіставляє опис із каталогом, показує схожі типи та ставить до трьох питань за один виклик. Перехід до схожого типу відкриває його наявний редактор, не змінюючи правил.
3. Відповіді передаються наступному виклику. Можна відповісти «Не знаю» або обрати **Підготувати чернетку з невідомими значеннями**.
4. Готова чернетка містить назву, опис, підтверджені вимоги, рекомендації, непідтверджені припущення, невідомі значення, інструкції для цілого виробу й окремого фронтального декору.
5. **Переглянути й редагувати перед збереженням** переносить чернетку у звичайний редактор нового типу. Тип ще не доданий. Користувач може змінити текст і назву.
6. Лише **Зберегти тип** записує новий тип у каталог через наявну перевірку даних, контроль редакції та резервну копію.

## Межі повноважень

Роль отримує загальні правила та знімок поточного каталогу; результат перевіряється за JSON Schema і додатковими серверними обмеженнями. Вказувати можна лише справжні ID схожих типів. Генерації зображень, редагування каталогу чи коду в цій ролі немає. Інструменти заборонені промптом, runner працює read-only; це той самий механізм виконання, що й інші текстові ролі.

Вимоги користувача відокремлюються від рекомендацій моделі; вигадані точні розміри фурнітури заборонені інструкцією. Вміст відповіді все одно потребує людського перегляду. Помічник не вимірює геометрію та не підтверджує виробничу придатність.

Автоматичне додавання програмних полів для нового типу не реалізоване: варіанти конструкції описуються текстом у правилах. Назва нового типу та її унікальність перевіряються під час збереження; збіг із наявною назвою не перезаписує наявний тип.

## Відновлення та помилки

Опис, історія відповідей, останній результат і ID активного завдання зберігаються в localStorage поточного браузера. Закриття вікна або оновлення сторінки не створює новий SDK-запит: для продовження потрібно знову відкрити помічника. Якщо є активне завдання, він відновлює опитування його статусу.

Усі запуски використовують спільну чергу завдань застосунку: одночасно виконується одне завдання. Є скасування та загальний таймаут. Запит і відповіді SDK зберігаються в `artifacts/runs/<job-id>/`. Скасований або перерваний запит не публікує чернетку в каталог. Уже виконані запити можуть використати ліміти підписки.

Каталог може змінитися за час підготовки чернетки. Редактор використовує редакцію каталогу, з якою працював помічник; застарілий результат не обходить захист від перезаписування нових правил.

## Перевірка реалізації

Автоматичні тести перевіряють структуру питань і чернетки, справжні ID схожих типів, повторні раунди з відповідями, явне завершення з невідомими значеннями, захист від подвійного натискання, відновлення чернетки після перезавантаження та відсутність запису в каталог до користувацького збереження. Відповіді SDK у цих тестах контрольовані. Живий запуск із реальною моделлю потрібно перевірити після перезапуску сервера зі звичайного Terminal.
