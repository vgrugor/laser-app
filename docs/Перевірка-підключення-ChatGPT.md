# Перевірка підключення через план ChatGPT

Дата перевірки: 18 жовтня 2026 року.

## Уточнення області висновку

**Оновлення за фактичною SDK-пробою:** зі звичайного Terminal успішні text, vision, generation та edit. Обидва PNG відкрито й візуально перевірено. Отже, описана нижче заборона генерації окремого OAuth-маршруту не поширюється на вже перевірений запуск нативного Codex SDK. Деталі всіх чотирьох тестів — у [SDK-пробі](SDK-проба.md).

Початкова перевірка нижче стосується конкретно Sign in with ChatGPT / ChatGPT plan usage через публічний Responses endpoint. Вона **не перевіряла нативний Codex SDK або стандартний Codex app-server з його власним входом через ChatGPT**. Тому висновок не можна використовувати як доказ неможливості всього циклу через локальний Codex.

Офіційний Codex SDK керує локальними сесіями; Codex підтримує ChatGPT sign-in. Документація зображень описує вбудовану генерацію в інтерактивних сесіях із витратою загальних лімітів Codex. Але те, що вона є в інтерактивному клієнті, ще не доводить її доступність у конкретному SDK/non-interactive запуску. Потрібен окремий end-to-end тест цього маршруту; він поки не проводився.

Рекомендована наступна перевірка: локальний Codex через SDK зі штатною авторизацією; текстова відповідь; аналіз наявного зображення; наявність і виконання вбудованої генерації; редагування збереженого файла. Не читати й не переносити токени вручну та не замінювати непідтверджену генерацію API-викликом.

Джерела уточнення: [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk), [Authentication](https://learn.chatgpt.com/docs/auth), [Image generation](https://learn.chatgpt.com/docs/image-generation). OpenAI Agents SDK, Codex SDK та Agents API не вважати одним продуктом; вибір оркестратора сам по собі не змінює спосіб авторизації виконавця.

## Висновок щодо початкового OAuth-маршруту

Решта документа зберігає історію початкової перевірки до SDK-проб. Формулювання про невиконані запити стосуються лише тієї початкової перевірки. Запланована вище перевірка нативного SDK вже завершена успішно.

Офіційний маршрут ChatGPT plan usage може бути основою текстових ролей і аналізу зображень відповідною моделлю, але не всього циклу Plywood Flow: генерація зображень у цьому маршруті зараз не підтримується. Не переносити можливості інструментів цього чату на можливості самостійного застосунку.

| Вхідні зображення | Підтримуються моделями, які приймають такі входи | Офіційна документація; власний запит не запускався |
| Генерація та редагування зображень | Інструмент image generation прямо не підтримується маршрутом ChatGPT plan usage | Офіційні preview limitations; тестова генерація не запускалася |

Доступ до конкретних моделей, текстового inference й аналізу картинок із Plywood Flow ще не підтверджено успішним запитом. Статус входу CLI цього не доводить. Підключення застосунку потребує документованої інтеграції, а не читання або копіювання його особистого кешу авторизації.

## Важливі обмеження інтеграції

- Для офіційного планового маршруту HTTP використовуються `store: false`, `stream: true` та контекст у `input`.
- Серед непідтримуваних hosted-інструментів прямо перелічено image generation. Локальні інструменти Codex — окремий механізм; самі по собі вони не створюють права доступу до генератора.
- Встановлений і авторизований Codex не означає, що сторонній браузерний застосунок успадковує всі інструменти настільного чату.
- Підписка не є безлімітною; допустимі запити використовують її наявні ліміти.
- Не використовувати приватні backend-api endpoints ChatGPT, витягування токенів із кешу чи автоматизацію вебінтерфейсу як прихований API.

## Практичні маршрути

1. **Без окремого платного API для зображень:** Plywood Flow зберігає проєкт, правила й завдання; зображення генеруються та редагуються в чаті, результат додається назад. Текстові ролі можна інтегрувати окремо після перевірки офіційного входу. Передавання картинки залишається явним кроком.
2. **Змішаний автоматичний маршрут:** текстові ролі й аналіз через належну інтеграцію плану, зображення через окремо налаштований image API. Потребує оплати image API, перевірки доступності й узгодження бюджету.
3. **Єдиний API-маршрут:** текстові ролі, аналіз і картинки через налаштований API-проєкт. Потребує ключа й окремої оплати; підключення поки не погоджене.

Жоден із варіантів не активований цією перевіркою. API-ключі й OAuth-токени не запитувалися та не записувалися, новий вхід не запускався, inference-запити й платні генерації не виконувалися.
