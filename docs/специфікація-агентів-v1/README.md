# Специфікація агентів — версія 1.0

18 жовтня 2026 року. Етап 2: контракт роботи системи та початкові інструкції ролей. Це документація для реалізації, а не запущені агенти чи готовий інтерфейс.

Залежність: база знань «база-знань-v1», версія 1.0, розташована поруч із цією папкою. В архів специфікації база не дублюється; зберігати обидві папки поруч. Правила технології та палітра читаються з бази, а не переписуються в кожну роль.

## Ролі

| ID | Роль | Результат |
|---|---|---|
| coordinator | [Координатор](ролі/01-координатор.md) | Стан проєкту, маршрутизація, запити користувачу |
| concepts | [Автор концепцій](ролі/02-концепції.md) | 10 текстових напрямків |
| constructor | [Конструктор декору](ролі/03-конструктор.md) | План частин, операцій, кольорів і композиції |
| prompt_author | [Автор промпту](ролі/04-промпт.md) | Інструкція генерації або точкового редагування |
| generator | [Генератор](ролі/05-генератор.md) | Растрові файли декору та вигляду виробу |
| technical_reviewer | [Технічний перевіряльник](ролі/06-технічна-перевірка.md) | Порушення й невиконані перевірки |
| art_reviewer | [Художній редактор](ролі/07-художня-перевірка.md) | Оцінка композиції та конкретні пропозиції |

Це сім логічних ролей. На першій реалізації вони можуть використовувати одну мовну модель з окремими інструкціями та окремими викликами; генерація зображень потребує відповідного інструмента. Сім одночасних незалежних процесів не є вимогою.

## Що визначено й що лишається реалізувати

Визначено входи й виходи, людські рішення, повідомлення про порушення, повторні перевірки, обмеження циклу, збереження та приймальні сценарії. Поки не вибрано середовище виконання, постачальника генерації, моделі, бюджет або платформу інтерфейсу. Не заявляти, що ці ролі вже автоматично перевіряють картинки.

Наступний етап — прототип інтерфейсу та керування цим сценарієм. Підключення реальної генерації повинно мати явний стан: демонстрація / працююча інтеграція.
