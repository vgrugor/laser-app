# Локальна інтеграція Codex SDK

Реалізована 18 жовтня 2026 року. Це перший робочий маршрут інтерфейс → локальний сервер → SDK; повний запуск із реальною моделлю з цього сервера ще потребує перевірки у звичайному Terminal.

## Запуск

У звичайному Terminal:

```sh
cd /Users/vlad/projects/laser-app
sh scripts/start.command
```

Відкрити http://127.0.0.1:8765/. Старий самодостатній HTML у Documents не містить цієї інтеграції. Якщо порт зайнятий, зупинити попередній сервер через Ctrl+C. Альтернативний порт: `PORT=8766 sh scripts/start.command`, але браузерне сховище на іншому порту буде окремим.

SDK уже встановлено в цьому проєкті. Для нового встановлення з Node.js/npm: `npm install`, потім `npm start`. Без npm є наявний installer `python3 scripts/install-codex-probe.py`. Скрипт запуску знаходить Node у PATH або використовує наявний runtime Codex на цьому комп'ютері.

## Використання

1. Створити проєкт, описати задум і вказати доступні кольори.
2. «10 концепцій» запускає концептуаліста. Він добирає підмножину обраних кольорів; натискання концепції застосовує її палітру й обрамлення.
3. Вибрати концепцію та «Підготувати завдання».
4. «Згенерувати декор і виріб» виконує послідовно: конструктор → автор промптів → фронтальний master → preview за master → візуальна перевірка пари.
5. Переглянути обидва види та зауваження. План і фактичні промпти розгортаються в панелі ШІ.
6. Додати власну правку або перенести зауваження ШІ до правок. «Застосувати правки» виконує один цикл: новий план і промпти, редагування master, новий preview та повторна перевірка. Самовільного нескінченного циклу немає.
7. «Перевірити пару» повторює візуальний огляд наявних файлів. Перевірка не змінює зображень і не дає погодження від імені користувача.

Кнопка «Скасувати» перериває активний SDK-запуск. Одночасно виконується одне завдання; обмеження всього маршруту — 20 хвилин. Уже виконані запити можуть використати ліміти підписки навіть при скасуванні.

## Зберігання

Браузер зберігає проєкти, зображення як data URL, версії, план, промпти та звіт. JSON-експорт містить ці дані; імпорт зберігає aiData для повторення, але скидає погодження та активне завдання. Результат перевірки після імпорту потрібно отримати знову.

`artifacts/runs/<job-id>/` містить request.json, job.json, відповіді ролей, input/reference-зображення, master.png, preview.png і діагностику помилок. Каталог виключено з Git. Фактичні PNG перевіряються за дозволеним шляхом, сигнатурою та розміром; для результатів записуються SHA-256 і розміри в пікселях. Запит містить поточну редакцію без історії версій.

Результат прив'язується до SHA-256 параметрів, концепції, референсу, зображень, правок і зафіксованих рішень. Якщо вони змінилися під час запуску, автоматична заміна забороняється; файли залишаються на диску. Оновлення сторінки відновлює спостереження за завданням із браузерного сховища. Після перезапуску сервера незавершене завдання позначається interrupted; автоматично повторно оплачувані/лімітовані запити не запускаються.

Якщо збережено master, але preview або перевірка не вдалися, доступний частковий результат додається в проєкт. Старий preview залишається позначеним як застарілий. Якщо перевірка не завершена, її позитивний результат не вигадується.

## Правила й доступ

Сервер читає основну базу `docs/база-знань-v1`, перевіряє хеші застосованих Markdown-файлів і палітри за manifest. Передає технічні вимоги, дизайн, технології, правила об'єктів і виробів. Історичні приклади й відкриті питання не є вхідними інструкціями цього маршруту. У результаті записує версію, хеш manifest, хеш палітри й перелік файлів.

Використовується офіційний `@openai/codex-sdk` 0.163.0 зі штатним входом ChatGPT. API-key змінні прибираються зі середовища дочірнього процесу, токени вручну не читаються. Текстові ролі — read-only; генератор — workspace-write із робочим каталогом окремого завдання. Успадковані sandbox-параметри не вимикаються. Вебпошук вимкнений, погодження не запитуються, тому операції, які його потребують, мають завершитися помилкою. Інструменти текстовим ролям заборонено промптом; окремого технічного tool allowlist у цьому варіанті немає.

HTTP слухає тільки 127.0.0.1, перевіряє Host/Origin, для POST потрібен випадковий токен поточного сервера. Публікація статичних файлів через Sites не запускає цей локальний backend.

## Перевірено та обмеження

Автоматичні тести перевіряють межі матеріалу й палітри, manifest, шляхи й формати зображень, послідовність ролей, передачу master у preview, правки, часткові результати, HTTP, скасування, перезапуск, застарілі відповіді та погодження. У тестах відповіді моделей підмінені контрольованими результатами; це не доказ якості реальної генерації.

Інтерфейс відкрито в браузері, кнопка концепцій успішно створила завдання й запустила SDK. Реальний SDK у сервері, запущеному агентом, завершився помилкою ініціалізації `Operation not permitted`; той самий sandbox-блокер був у пробах. Потрібно запускати сервер зі звичайного Terminal, де окремі text/vision/generation/edit-проби вже успішні. Успіх повного маршруту через інтерфейс ще не заявляється.

Геометрію ≥2 мм, фактичну кількість деталей, посадку фурнітури та придатність до різання перевіряє користувач у CAD. Перевіряльник зображень може помилятися; точне збереження дрібних штрихів при правках не гарантоване.

Джерело API SDK: [офіційна документація Codex SDK](https://learn.chatgpt.com/docs/codex-sdk); фактичні сигнатури перевірено у встановленому пакеті.
