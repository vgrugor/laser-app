# Фактична проба Codex SDK

Дата: 18 жовтня 2026 року.

## Актуальний підсумок: текст, vision, генерація та редагування працюють

Підтверджено звітами зі звичайного Terminal:

- text: turn.completed та `SDK_TEXT_OK`;
- vision: модель описала фронтальний декор магнолії та правильно нарахувала 7 пелюсток. Без контексту назвала його панно, тому тип виробу потрібно явно передавати перевіряльнику;
- generation: turn.completed, повернений шлях `GENERATED_IMAGE`, реальний PNG відкрито для візуального огляду. Файл скопійовано в artifacts/sdk-probe/generation.png, його розмір і SHA-256 записані в generation.json.

Редагування також успішне: turn.completed та `EDITED_IMAGE`, перевірений PNG збережено в artifacts/sdk-probe/edit.png (2 625 316 байтів, 1254×1254; SHA-256 у edit.json). Візуальне порівняння підтвердило додану чорну прямокутну рамку та загальне збереження композиції, форми квітки й палітри. Дрібні штрихи та текстура частково змінилися; піксельна тотожність не підтверджується.

Отже, в поточному локальному середовищі користувача фактично підтверджені чотири можливості через SDK зі штатним входом ChatGPT без переданого API-ключа. Попередні невдалі запуски з обмеженого середовища агента не спростовують цього результату. Нижче вони збережені як історія діагностики.

Це перевірка конкретного локального середовища, а не гарантія доступності для всіх облікових записів чи моделей. Інтерфейс тепер підключено через локальний сервер (див. Локальна-інтеграція-SDK.md); повний маршрут із моделями потребує перевірки зі звичайного Terminal. Виробничу придатність тестових зображень не перевірено.

## Підготовлено

- Офіційний `@openai/codex-sdk` 0.163.0 та його штатний `@openai/codex` 0.163.0 встановлено локально в node_modules. Пакети завантажено з npm registry та перевірено за dist.integrity. Глобальні пакети не змінювалися.
- У середовищі виконання немає npm, тому використано scripts/install-codex-probe.py. На звичайному середовищі достатньо `npm install`.
- Скрипт scripts/probe-codex-sdk.mjs використовує офіційний SDK, не передає apiKey і прибирає API-key змінні зі середовища дочірнього процесу. Файли авторизації не читаються вручну.
- Штатний вхід Codex раніше підтверджено командою login status: Logged in using ChatGPT.
- Текст і vision запускаються read-only; generation — workspace-write для збереження зображення, без запитів, які потребують погодження, і без вебпошуку. Generation дозволяє прочитати інструкцію imagegen, але забороняє змінювати код і підміняти генерацію API-викликами чи малюванням кодом.
- Звіти зберігаються в artifacts/sdk-probe, виключеній із Git. Токени авторизації до звітів не записуються.

## Результат запуску в середовищі агента

### Оновлення: текстовий тест зі звичайного Terminal успішний

Користувач виконав тест; результат також підтверджено читанням artifacts/sdk-probe/text.json: status completed, подія turn.completed та finalResponse `SDK_TEXT_OK`. Текстовий inference через фактичний SDK зі штатним входом працює поза обмеженим середовищем агента. Наступні успішні аналіз, генерація та редагування наведено в актуальному підсумку вище. Таблиця нижче описує попередні невдалі запуски саме в середовищі агента.

| Етап | Фактичний результат |
|---|---|
| Завантаження та імпорт SDK | Успішно |
| Запуск SDK із CLI настільного застосунку | Помилка ініціалізації до відповіді моделі |
| Доступ до службових баз Codex | Початкову заборону запису усунуто після дозволу на конкретні runtime-шляхи |
| Повтор із відповідним штатним CLI 0.163.0 | Та сама помилка ініціалізації |
| Повтор без IPC-підключення до інструментів настільного host | Та сама помилка; змінні sandbox і permission profile збережено |
| Текстова відповідь моделі | Не отримана |
| Аналіз зображення | Не запускався через провал базового старту |
| Генерація та редагування зображення | Не перевірені |

Остаточна помилка: `failed to initialize in-process app-server client: Operation not permitted (os error 1)`.

Це відмова локального запуску в поточному обмеженому середовищі, а не відповідь сервісу про тариф або інструмент image generation. Точна заборонена системна операція з цього повідомлення невідома. Немає доказу успішного inference чи успішного/невдалого доступу до генератора. Параметри обходу sandbox не застосовувалися.

## Відтворення зі звичайного Terminal

У корені проєкту:

```sh
sh scripts/probe-codex-sdk.command text
```

Очікувана відповідь після успішного звернення: `SDK_TEXT_OK`. У файлі artifacts/sdk-probe/text.json має бути status completed та отримана відповідь, а не лише створений процес.

Лише після цього:

```sh
sh scripts/probe-codex-sdk.command vision
sh scripts/probe-codex-sdk.command generation
```

Vision передає наявний фронтальний декор магнолії. Generation просить лише вбудовану генерацію та забороняє fallback до API, shell, SVG або браузера. Якщо інструмента немає, очікується `IMAGE_GENERATION_UNAVAILABLE`; це треба розрізняти з мережевою помилкою чи незапущеним процесом. Успіх генерації підтверджується реальним файлом зображення або доступним артефактом, а не словами моделі.

Для редагування використовується перевірений artifacts/sdk-probe/generation.png через local_image. Наявність image input сама по собі не означає успішного редагування. Після команди edit результат зберігається як edit.png лише якщо SDK повернув дійсний дозволений шлях до PNG.

Запуски можуть використовувати ліміти поточної підписки ChatGPT. Додатковий API-ключ скрипт не використовує. Стандартна сесія SDK може записувати службові дані у штатний каталог Codex; окремих змін авторизації скрипт не робить.
